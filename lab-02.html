Configure Browser Access for Third Parties

Publish the internal HVAC web application and validate clientless access from the remote Linux client.

4 tasks Approx. 20 minutes Dedicated tenant
Lab objectives

What you will accomplish

  • Create and enroll an App Connector.

  • Validate external DNS and application access without Client Connector.
Technical concept

Why ZPA Browser Access exists

Browser Access provides clientless access to private web applications. The user authenticates in a normal browser, ZPA applies access policy, and an App Connector reaches the private application—without requiring Zscaler Client Connector on the user device.

Where it adds value

Third-party and unmanaged-device access

Use Browser Access when installing Client Connector is not practical—for example, contractors, partners, BYOD devices, or platforms you do not manage. Access remains application-specific rather than exposing the private network.

What it supports

Private web applications

Browser Access is designed for HTTP/HTTPS applications. Users access an external Browser Access URL, authenticate, and are connected only to applications allowed by ZPA policy.

Certificate choice

Managed vs. Unmanaged / Custom certificate

The certificate presented to the user protects the Browser Access HTTPS endpoint. The difference is mainly who owns the certificate and public-DNS lifecycle.

Managed

Zscaler manages the public-facing certificate

You choose an available external domain prefix/suffix and Zscaler manages the Browser Access certificate for the selected managed domain. This is the simplest choice for a lab or when you do not need to preserve an existing public hostname.

Unmanaged / Custom

Your organization manages the certificate

You provide/select the web-server certificate and manage its issuance, renewal, and public DNS. Use this when you need an organization-controlled domain, certificate, or PKI workflow.

i
How this maps to Lab 2

The HVAC application uses Browser Access + Managed certificate, so the learner can focus on publishing and securing the private application rather than building a certificate/DNS lifecycle manually.

2.2

Activate the App Connector

Enroll the Corp ZPA Connector in OnPrem.

  1. Open Corp ZPA Connector in CloudShare. Select its console (CON) and sign in as admin with lab password Zscaler1!. Display the enrollment token using the lab-image convenience below.
    cat /etc/issue
  2. If a fresh token is needed, use this reset only on the assigned training connector.
    !
    Reset clears connector enrollment state

    The next commands delete local connector state. Do not run them on a production connector or the Log Streaming Connector. If this lab VM is already correctly enrolled, ask the instructor before resetting it.

    sudo systemctl stop zpa-connector
sudo su
rm -rf /opt/zscaler/var/*
systemctl start zpa-connector
cat /etc/issue
exit
  3. Return to the Experience Center and open App Connectors.
    Infrastructure›Private Access›Component›App Connectors

    Documented route; portal menu versions can differ. Search by the feature name if needed.

    Search Menu → App Connectors
    Zscaler Help: App Connectors ↗
    Select Add.
    SettingValue
    GroupOnPrem
    Enrollment TokensCurrent token from this VM; select Add to include it
  4. Select Save. Refresh until Connection Health is Connected (the source suggests about 30 seconds). Open the connector to review its OS, location, IP addresses and uptime.
i
Token retrieval is lab-specific

The /etc/issue display is a convenience of this training image. If no token appears, use the VM console output or contact the instructor. Regenerate only when the token is missing, invalid or expired.

✓
Expected result

The Corp ZPA Connector is enrolled in OnPrem and reports Connected.

2.4

Test Browser Access to HVAC

Use the external domain from the remote Linux VM.

Search Menu → Browser Access
Zscaler Help: Browser Access ↗
  1. Find the HVAC entry and copy its External Domain. Do not substitute the internal HVAC FQDN.
  2. Open Remote Linux Client PC in CloudShare. Sign in as admin with Admin-123!. Open Terminal and query the external domain.
    dig <HVAC-External-Domain>
    Confirm DNS returns Zscaler public addresses/CNAMEs. If resolution fails, use the lab command sudo systemd-resolve --flush-caches where available or ask the instructor before restarting the VM.
  3. Open https://<HVAC-External-Domain> in Chrome. Authenticate to the lab identity service with the HVAC test account.
    SettingValue
    Usernamehvac@<Student FQDN>
    Documented test-user passwordAdmin-123!; use an instructor-provided replacement if specified
    If a certificate warning appears, confirm the hostname matches your assigned lab domain before following the instructor’s lab-only exception.
  4. Confirm the Safemarch HVAC Control page loads.
