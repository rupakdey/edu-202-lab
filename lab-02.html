Configure Browser Access for Third Parties

Provide a third-party user with secure, clientless access to the internal Safemarch HVAC application. You will provision the connector path, publish the application with Browser Access, apply an access policy, and validate the connection from a remote Linux client.

4 tasksApprox. 20 minutes
Lab objectives

What you will accomplish

  • Provision an App Connector to connect the internal HVAC application to the Zero Trust Exchange.
  • Publish the HVAC application with Browser Access and define the required access policy.
  • Validate Browser Access by testing the end-to-end connection without Zscaler Client Connector.
Technical concept

Why ZPA Browser Access exists

Browser Access provides clientless access to private web applications. The user authenticates in a normal browser, ZPA applies access policy, and an App Connector reaches the private application—without requiring Zscaler Client Connector on the user device.

Where it adds value

Third-party and unmanaged-device access

Use Browser Access when installing Client Connector is not practical—for example, contractors, partners, BYOD devices, or platforms you do not manage. Access remains application-specific rather than exposing the private network.

What it supports

Private web applications

Browser Access is designed for HTTP/HTTPS applications. Users access an external Browser Access URL, authenticate, and are connected only to applications allowed by ZPA policy.

Certificate choice

Managed vs. Unmanaged / Custom certificate

The certificate presented to the user protects the Browser Access HTTPS endpoint. The difference is mainly who owns the certificate and public-DNS lifecycle.

Managed

Zscaler manages the public-facing certificate

You choose an available external domain prefix/suffix and Zscaler manages the Browser Access certificate and related CNAME workflow. This is the simplest choice for a lab or when you do not need to preserve an existing public hostname.

Unmanaged / Custom

Your organization manages the certificate

You provide/select the web-server certificate and manage its issuance, renewal, and public DNS. Use this when you need an organization-controlled domain, certificate, or PKI workflow.

How this maps to Lab 2

The HVAC application uses Browser Access + Managed certificate, so the learner can focus on publishing and securing the private application rather than building a certificate/DNS lifecycle manually.

2.1

Provision an App Connector Group

Create the connector group that will represent the on-premises application environment.

  1. On Corp: Client PC 1, sign in as student with password Admin-123!, then open the Experience Center.
  2. Open App Connector Groups.
    Search menu → App Connector Groups
  1. Select Add and configure the group:
    SettingValue
    NameOnPrem
    StatusEnabled
    DescriptionOptional
    Signing CertificateConnector
    Other ConfigurationsLeave at default
    App Connector LocationSelect the location closest to you / your current city
  1. Select Next, keep the remaining settings at their defaults, and accept the maintenance-window acknowledgement if it appears.
  2. Select Save and confirm that OnPrem appears in the App Connector Groups list.
✓
Expected result

The enabled OnPrem App Connector Group exists and is ready for connector enrollment.

2.2

Activate the App Connector

Generate an enrollment token, register the connector with the OnPrem group, and verify its status.

  1. Open the Corp: ZPA App Connector VM. The connector displays an OAuth token when it first starts. If you need shell access, sign in with:
    Usernameadmin
    Passwordzscaler
    To display the current token from the shell, run:
    cat /etc/issue
  1. Generate a fresh token by stopping the service, deleting the existing token files, and starting the service again:
    sudo systemctl stop zpa-connector
    sudo find /opt/zscaler/var/ -type f -name '*' -delete
    sudo systemctl start zpa-connector

    Use the newly displayed OAuth token. If a token is expired or rejected, repeat this step.

  1. In the Experience Center, open App Connectors and select Add.
    Search menu → App Connectors
  2. Configure the connector:
    SettingValue
    GroupOnPrem
    Enrollment TokenEnter the token generated above, then select Add
    Signing CertificateConnector
    Select Save.
  1. Confirm that the connector appears in the list. Open the connector to review details such as Host OS, Public Service Edge, location, IP addresses, and uptime.
✓
Expected result

The App Connector is registered in the OnPrem group and appears in the tenant. After a short delay, Connection Health should report Connected.

2.3

Create the HVAC Application and Access Policy

Publish the internal HVAC service through Browser Access and allow web-browser access to it.

  1. Open App Segments and select Add Application Segment.
    Search menu → App Segments
  1. Define the HVAC application:
    SettingValue
    NameHVAC
    StatusEnabled
    Application<Student ID>.hvac.safemarch.com
    Access TypeBrowser Access
    Certificate TypeManaged
    External URLDomain Prefix = hvac; choose any available domain suffix
    Internal URLProtocol = HTTP; Port = 80
    Client Connector AccessTCP Port Range = 80–80
    Select Next.
  2. Create the supporting groups:
    ObjectSettings
    Segment GroupCorpApps · Enabled
    Server GroupCorpServers · App Connector Group = OnPrem
    Continue through Next → Review → Save.
  1. Create the access rule. After saving the segment, select Edit Policy, or open Access Policy from the Experience Center.
    Search menu → Access Policy
  2. Select Add and configure:
    SettingValue
    Rule NameAllow HVAC
    Rule ActionAllow Access
    Application SegmentHVAC
    Client TypeWeb Browser
    Select Save.
✓
Expected result

The HVAC Browser Access application is published through CorpServers / OnPrem, and the Allow HVAC policy permits Web Browser access.

2.4

Test Browser Access to the HVAC Application

Validate the clientless connection from the remote Linux system.

  1. Open Browser Access in the Experience Center and copy the External Domain for the HVAC application.
    Search menu → Browser Access
  1. Open Remote: Linux Client PC and sign in:
    UsernameAdmin
    PasswordAdmin-123!
  2. Open Terminal and verify DNS resolution for the copied external domain:
    dig <External-Domain>
    Confirm that the response contains Zscaler public addresses and Zscaler/GSLB hostnames.
i
If DNS resolution fails

Flush the Linux DNS cache with sudo systemd-resolve --flush-caches (password Admin-123!) or restart the VM, then retry the lookup.

  1. Open Chrome and browse to the copied External Domain. If a privacy warning appears in the lab environment, select Advanced and continue.
  2. Authenticate to the HVAC application:
    Usernamehvac@<Student FQDN>
    PasswordAdmin-123!
  3. Confirm that the Safemarch HVAC Control page opens.
✓
Expected result

The remote Linux client resolves the Browser Access URL through Zscaler and can sign in to the Safemarch HVAC application without Zscaler Client Connector.
