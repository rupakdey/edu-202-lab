Lab 9 · Hands-on

Automate with Zscaler OneAPI

Configure an OAuth API client, authenticate Postman and create an App Connector Group through OneAPI.

5 tasks Approx. 20 minutes Dedicated tenant
Lab objectives

What you will accomplish

  • Fork the verified OneAPI collection and environment.
  • Create an API client and gather the required variables.
  • Test GET requests and create a connector group with POST.
9.1

Prepare Postman

Use the preinstalled desktop application or the web client.

  1. On Corp Client PC 1, launch the preinstalled Postman desktop app. Alternatively use Postman on the web ↗ or the official download page ↗.
  2. Create a free account or sign in. Open your own training workspace.
✓
Expected result

Postman opens and you can use a personal training workspace.

9.2

Fork the OneAPI Collection

Import both the collection and its environment.

  1. Select Home → Public API Network. Search for Zscaler OneAPI and open the verified public collection.
  2. Right-click the collection and select Use / Fork. Enter a fork label and select the Zscaler OneAPI environment under Environments to Fork.
  3. Select Use / Fork Collection. Confirm both the collection and environment are present in your workspace.
✓
Expected result

The Zscaler OneAPI collection and matching environment are available in Postman.

9.3

Create the API Client and Gather Variables

Obtain authentication values and the ZPA customer identifier.

  1. In the Experience Center, open Service Portal. Copy the Authentication Service origin from the address bar, such as https://zs000834.zslogin.net. Remove /portal and any path/query suffix.
  2. Open API Clients and select Add API Client.
    Search Menu → API Clients
    Zscaler Help: API Clients ↗
    SettingValue
    NameTestClient
    StatusEnabled
    Access Token Validity90 minutes
    Client Authentication → Validation TypeSecret
  3. Select Add to generate the client secret. Copy it immediately into a private local training note or Postman’s local secret storage. It is shown only on creation; do not place it in this guide or a shared workspace.
  4. On Resources, assign the source lab’s roles and Save.
    SettingValue
    ZCCSuper Admin
    ZIASuper Admin
    ZPAAPI Full Access
    These are broad roles for the dedicated lab; use narrowly scoped roles for a production integration.
  5. Copy the saved Client ID. Use Search Menu → Linked Services to find the ZPA Tenant ID / Customer ID.
i
Keep the four values distinct

Authentication Service base URL, Client ID and Client Secret authenticate the API client. The ZPA Customer ID identifies the tenant used in ZPA requests; it is not the client identifier.

✓
Expected result

You have the tenant Authentication Service base URL, Client ID, Client Secret and ZPA Customer ID without exposing them in shared files.

9.4

Authenticate and Test GET Requests

Use the forked environment and a fresh OAuth token.

  1. Select the Zscaler OneAPI environment. Set the variables using Task 9.3; use the variable names exactly as defined in your fork.
    SettingValue
    zIdentityBaseUrlAuthentication Service origin, with no /portal suffix
    clientIDAPI Client ID
    clientSecretGenerated client secret
    customeridZPA Customer ID
  2. On the collection Authorization tab, choose Get New Access Token. Complete authentication, then select Use Token.
  3. Use Search Menu → Tokens to confirm an active token for your Client ID; a recent Issued at filter can help locate it.
  4. In Postman, expand Zscaler Client Connector → Devices → Get all enrolled devices. Select Send and confirm 200 OK.
  5. Run the GET Download device details as a CSV file request and verify the successful response and CSV content.
✓
Expected result

OAuth authentication succeeds and both read requests return successful responses for the assigned environment.

9.5

Create an App Connector Group through OneAPI

Use the tenant’s enrollment certificate ID in the POST body.

Infrastructure›Private Access›Component›App Connector Groups

Documented route; portal menu versions can differ. Search by the feature name if needed.

Search Menu → App Connector Groups
Zscaler Help: App Connector Groups ↗
  1. Review the existing groups. In Postman, open Zscaler Private Access → Enrollment Certificate Controller → Get all configured enrollment certificate details for the specific customer. Send the GET request and copy the appropriate signing/enrollment certificate id.
  2. Open Connector Group Controller → Add a new App Connector Group for Specified Customer. In Body, enter the source payload below and replace <Enrollment-Certificate-ID> with the ID returned by the previous request.
    {
  "name": "ZPALAB APPC Group",
  "description": "App Connector training Lab at San Jose",
  "latitude": "37.3382032",
  "longitude": "-121.886286",
  "location": "San Jose, CA, USA",
  "signingCertId": "<Enrollment-Certificate-ID>"
}
  3. Confirm the environment’s customer ID and active token, then Send. Verify 201 Created and inspect the returned group name/ID.
  4. Refresh App Connector Groups in the Experience Center and confirm ZPALAB APPC Group appears.
i
What this verifies

The POST creates an App Connector Group object; it does not enroll a connector or establish high availability by itself. Official App Connector Group API reference ↗

✓
Expected result

OneAPI returns 201 Created and the named group appears in the UI. No connector enrollment or HA outcome is implied.

✓
