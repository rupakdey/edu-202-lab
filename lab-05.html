Understand Privileged Remote Access

Build a browser-based Privileged Remote Access workflow for Windows RDP and Linux SSH targets. You will define PRA application segments, portal/console objects, stored credentials, policies, and then verify live sessions.

7 tasksApprox. 50 minutes
Lab objectives

What you will accomplish

  • Configure a Privileged Portal and Privileged Console within Zscaler's Privileged Remote Access (PRA) to enable clientless browser-based access to a Linux server using SSH, without installing the Zscaler Client Connector or browser plugins.
  • Configure a Privileged Application Segment to define and restrict access to only the target Linux and Windows systems.
  • Provision Privileged Policies to assign access rights to a specific external vendor user for a limited time frame.
  • Configure Privileged Credentials to provide the vendor with predefined credentials or require the vendor to authenticate with their own credentials during console access.
  • Validate privileged remote access by signing in as the assigned vendor user and establishing secure SSH and RDP sessions to the Linux server and the Windows server through the browser-based PRA portal.
Technical concept

Privileged Remote Access in one view

PRA extends ZPA for privileged administrative access to systems such as Windows and Linux servers. A user can launch RDP or SSH from a browser-based portal without receiving broad network access, while the organization controls credentials and session capabilities centrally.

Portal

Where the user starts

The Privileged Portal is the authenticated web entry point. It shows only the privileged consoles/resources that policy allows that user to access.

Console

How the session is presented

A Privileged Console represents the browser-based session to a specific PRA-enabled application, such as an RDP or SSH target.

Privileged credential

How target authentication can be controlled

ZPA can store or manage credentials used by the console. This lets an organization grant access without necessarily revealing the target-system password to the user.

Access policyWho may reach the PRA application?
Credentials policyWhich credential is mapped to which console/target?
Consoles policyWhat can the user do during the session?
Session controls

Control high-risk actions

Consoles policies can govern capabilities such as clipboard copy/paste, file upload/download, session recording, and whether permitted users can join, monitor, or share a live privileged session.

Security outcome

Privilege without network exposure

The user receives access to the approved administrative session—not general routed access to the server network. This makes PRA useful for vendors, contractors, and controlled administrator workflows.

How the Lab 5 objects fit together

Application Segment defines the RDP/SSH target → Portal is the user entry point → Console exposes the target in the browser → Privileged Credential + Credentials Policy handle target login → Consoles Policy controls session behavior.

5.1

Create the Application Segments

Define the Windows RDP and Linux SSH targets and permit access.

  1. Open App Segments and add a Privileged Remote Access segment for the Windows server.
    Search menu → App Segments
  2. Configure the RDP segment:
    SettingValue
    NamePRA_RDP1_win Svr
    Application10.0.0.1
    Access TypePrivileged Remote Access
    Protocol / PortRDP / 3389
    Connection SecurityAny
    Client Connector PortsRDP 3389; UDP 3389
    Segment GroupCorpApps
    Server GroupCorpServers
    Leave Common Configuration at default, review, and save.
  1. Create an Access Policy rule:
    Search menu → Access Policy
    SettingValue
    Rule NamePRA_Allow_Access
    Rule ActionAllow Access
    App Connector SelectionAll App Connector Groups
    ApplicationsPRA_RDP1_win Svr
    Save the rule.
  2. Create a second PRA segment for the Log Streaming Connector:
    SettingValue
    NamePRA_SSH2_Log_Streaming_Connector_PC
    Application10.0.0.20
    Access TypePrivileged Remote Access
    Protocol / PortSSH / 22
    Client Connector PortsSSH 22
    Segment GroupCorpApps
    Server GroupCorpServers
    Save it, then edit PRA_Allow_Access and add the new SSH segment to the Applications criteria.
✓
Expected result

Both the Windows RDP and Linux SSH targets are defined as PRA application segments and are permitted by PRA_Allow_Access.

5.2

Create the Portal

Create the browser-based PRA entry point.

  1. Open Privileged Portals and select Add.
    Search menu → Privileged Portals
  2. Configure:
    SettingValue
    NamePrivileged_Portal
    Certificate TypeManaged
    Portal URLpraportal
    Domain SuffixSelect any available suffix
    User Portal for Portal LinksNone
    Select Save.
✓
Expected result

The Privileged_Portal is available as the browser-based entry point for PRA users.

5.3

Create the Consoles

Expose the PRA targets as browser-accessible consoles.

  1. Open Privileged Consoles and select Add.
    Search menu → Privileged Consoles
  2. Choose Privileged_Portal and select both PRA application segments created in Task 5.1. Continue to the Consoles tab.
  1. Verify the generated console details: SSH should use port 22; RDP should use port 3389 with RDP connection security. Select Next.
  1. Review the configuration and select Save.
✓
Expected result

The portal contains SSH and RDP consoles for the two PRA application segments.

5.4

Create Privileged Credentials

Store credentials for the Windows and Linux targets.

  1. Open Privileged Credentials and create the Windows credential:
    Search menu → Privileged Credentials
    SettingValue
    NamePRA_windows
    TypeUserName-Password
    Usernameadministrator
    PasswordAdmin-123!
    Save it.
  1. Create the Linux credential:
    SettingValue
    NamePRA_Log_Streamming_Connector
    TypeUserName-Password
    Usernameadmin
    Passwordzscaler
    Save it.
✓
Expected result

Stored credentials exist for both the Windows and Linux PRA targets.

5.5

Create the Privileged Credential Policy

Map each stored credential to the correct target.

  1. Open Credentials Policy and create the RDP credential policy:
    Search menu → Credentials Policy
    SettingValue
    NamePRA_Credential_policy_RDP
    Privileged CredentialPRA_windows
    Application / IP criteria10.0.0.1
    Save it.
  1. Create the SSH credential policy:
    SettingValue
    NamePRA_Credential_policy_SSH
    Privileged CredentialPRA_Log_Streamming_Connector
    Application / IP criteria10.0.0.20
    Save it.
✓
Expected result

Each PRA target is associated with the correct stored credential through a credential policy.

5.6

Create the Consoles Policy

Apply session-control behavior to the PRA consoles.

  1. Open Consoles Policy and select Add.
    Search menu → Consoles Policy
  2. Configure:
    SettingValue
    NamePRA_Console_Policy
    Clipboard CopyEnable
    Record SessionEnable
    Join SessionEnable
    Share SessionMonitor
    Application criteriaSelect both PRA application segments from Task 5.1
    Select Save.
✓
Expected result

The PRA consoles use the configured session controls and apply to both lab targets.

5.7

Test and Verify

Launch RDP and SSH through the portal and verify the live sessions.

  1. On Corp: Client PC 1, log out of Zscaler Client Connector.
  2. Open the Experience Center, locate Privileged Portals, and select Launch for Privileged_Portal. Authenticate with your student tenant account if prompted.
    Search menu → Privileged Portals
  1. Select the Windows target 10.0.0.1 and start the RDP session through the browser.
  1. In the admin portal, open Privileged Remote Access → Live Sessions and verify the active RDP session.
    Search menu → Live Sessions
  2. Return to the privileged portal, select the Log Streaming Connector 10.0.0.20, and open the SSH session.
  3. Return to Live Sessions and verify the active SSH session.
✓
Expected result

The browser-based PRA portal can establish both RDP and SSH sessions, and the sessions are visible in PRA Live Sessions.
