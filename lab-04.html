Understand Privileged Remote Access

Build browser-based RDP and SSH access to the Windows server and Log Streaming Connector, then verify live sessions.

7 tasks Approx. 50 minutes Dedicated tenant
Lab objectives

What you will accomplish

  • Define PRA-enabled application segments for RDP and SSH.
  • Create the portal, consoles, stored credentials and policies.
  • Launch browser sessions and verify their visibility in Live Sessions.
Technical concept

Privileged Remote Access in one view

PRA extends ZPA for privileged administrative access to systems such as Windows and Linux servers. A user can launch RDP or SSH from a browser-based portal without receiving broad network access, while the organization controls credentials and session capabilities centrally.

Portal

Where the user starts

The Privileged Portal is the authenticated web entry point. It shows only the privileged consoles/resources that policy allows that user to access.

Console

How the session is presented

A Privileged Console represents the browser-based session to a specific PRA-enabled application, such as an RDP or SSH target.

Privileged credential

How target authentication can be controlled

ZPA can store or manage credentials used by the console. This lets an organization grant access without necessarily revealing the target-system password to the user.

Access policyWho may reach the PRA application?
Credentials policyWhich credential is mapped to which console/target?
Consoles policyWhat can the user do during the session?
Session controls

Control high-risk actions

Consoles policies can govern capabilities such as clipboard copy/paste, file upload/download, session recording, and whether permitted users can join, monitor, or share a live privileged session.

Security outcome

Privilege without network exposure

The user receives access to the approved administrative session—not general routed access to the server network. This makes PRA useful for vendors, contractors, and controlled administrator workflows.

i
How the Lab 4 objects fit together

Application Segment defines the RDP/SSH target → Portal is the user entry point → Console exposes the target in the browser → Privileged Credential + Credentials Policy handle target login → Consoles Policy controls session behavior.

4.1

Create the PRA Application Segments

Define both administrative targets and permit access.

Policies›Access Control›Private Applications›Defined Application Segments

Documented route; portal menu versions can differ. Search by the feature name if needed.

Search Menu → Application Segments
Zscaler Help: Application Segments ↗
  1. Select Add Application Segment. Create the Windows target, then select the existing groups and Save.
    SettingValue
    NamePRA_RDP1_win Svr
    Applications10.0.0.1 · Corp Win Svr 2025
    Access TypePrivileged Remote Access
    Protocol / PortRDP / 3389
    Connection SecurityAny
    Client Connector AccessDefault Port Ranges: RDP (TCP 3389); UDP: 3389
    Common ConfigurationLeave defaults
    Segment Group / Server GroupCorpApps / CorpServers
  2. Select Edit Policy → Add Rule and add the access rule.
    SettingValue
    Rule NamePRA_Allow_Access
    Rule ActionAllow Access
    App Connector Selection MethodAll App Connector Groups
    Applications criterionPRA_RDP1_win Svr
  3. Create the Linux target with the same segment/server groups, then Save.
    SettingValue
    NamePRA_SSH2_Log_Streaming_Connector_PC
    Applications10.0.0.20 · Corp Log Streaming Connector
    Access TypePrivileged Remote Access
    Protocol / PortSSH / 22
    Client Connector AccessDefault Port Ranges: SSH (TCP 22)
    Common ConfigurationLeave defaults
    Segment Group / Server GroupCorpApps / CorpServers
  4. Edit PRA_Allow_Access. Add the SSH application segment alongside the Windows segment, then Save.

Expected result

Both PRA segments exist and PRA_Allow_Access includes the Windows and Linux targets.

4.7

Launch and Verify PRA Sessions

Test the two consoles from the privileged portal.

  1. On Corp Client PC 1, log out of Zscaler Client Connector. Keep the Experience Center administrator browser session available.
  2. Open Privileged Portals and select Launch for Privileged_Portal. If prompted, sign in with your student tenant account.
    Search Menu → Privileged Portals
    Zscaler Help: Privileged Portals ↗
  3. Open the Windows console (10.0.0.1). Confirm the remote Windows desktop opens using the configured credential.
  4. In the administrator portal, open Live Sessions and confirm the active RDP session.
    Search Menu → Live Sessions
    Zscaler Help: Live Sessions ↗
  5. Open the Linux console (10.0.0.20) and confirm the SSH terminal opens. Check Live Sessions again for the SSH session.
✓
Expected result

RDP and SSH sessions open through the browser portal and appear in Live Sessions with the corresponding protocols and targets.
