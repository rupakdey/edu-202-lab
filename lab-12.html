Manage Incidents with Zscaler Workflow Automation

Use the Solutions Demo Center to investigate DLP incidents and workflow automation. You will switch Client Connector to the SDC identity, review incident evidence, update metadata, test notification/escalation, and inspect automated workflow logic.

5 tasksApprox. 20 MinutesRead-only SDC
Lab objectives

What you will accomplish

  • Change the status and priority of data protection incidents.
  • Escalate incidents to appropriate stakeholders for review.
  • Notify end users via email to provide coaching or request justification.
  • Identify incident metadata, trigger data, and violation content.
  • View and understand automated workflow templates and mappings.
12.1

Enroll with Zscaler Client Connector

Switch Client Connector from the learner tenant to the SDC IT identity.

  1. On Corp: Client PC 1, open Zscaler Client Connector and select Log Out.
  1. Sign in to Client Connector with the IT department SDC identity supplied for the course. At the IdP prompt, use the IT department username and the SDC session password.
  2. Allow Client Connector a few minutes to initialize. Confirm Internet Security = ON and Network Type = Off-Trusted Network.
✓
Expected result

Corp: Client PC 1 is enrolled with the SDC IT identity and Internet Security is active.

12.2

View Current DLP Incidents

Open an incident and inspect its metadata and trigger data.

  1. Sign in to the Experience Center with the SDC administrator credentials and open Workflow Automation → Incidents.
    Search menu → Incidents
  1. Open the first incident by selecting its Transaction ID. Review the metadata in Overview and Violation Details.
  1. Scroll to Violation Content and expand View Trigger Data to inspect the content that triggered the DLP violation.
✓
Expected result

You can identify the incident metadata, violation details, and the data that triggered the DLP incident.

12.3

Modify Incident Metadata

Update the incident status and priority, then review the audit trail.

  1. From the Incident Details page, open Actions, set Status = Investigating, and enter Test in the Note field.
  1. Select Assign Priority and set Priority = High if it is not already High.
  1. Refresh the browser. Confirm the new Status and Priority, then review State Changes to see the history entries.
✓
Expected result

The selected incident is marked Investigating, has High priority, and the changes are recorded in State Changes.

12.4

Test User Notification and Escalation Workflows

Notify the end user, add an approver, and test incident escalation.

  1. From Incident Details, open Actions → Notify User. Choose a language, enter Please justify uploading this document for testing purposes of HandsOnLab, and submit.
  1. Review State Changes and confirm the notification action is recorded. You can continue even if the originator does not respond during the lab.
  2. Open Workflow Automation → Approvers, add yourself with your name and email address, and save.
    Search menu → Approvers
  1. Return to the incident, open Actions → Escalate, select your newly created approver, and save.
  1. Open your personal email, find the DLP Incident Notification (check spam if needed), follow the link, select Approved, enter a reason, and submit. Confirm the notification/escalation actions are recorded in State Changes.
✓
Expected result

The lab incident records both the end-user notification and the approver escalation workflow.

12.5

Explore Automated Workflows

Review workflow templates and the mappings that determine when they run.

  1. Open Workflow Automation → Workflow Templates. In the Auto Escalate row, select the View Workflow Template icon and review the flow logic.
    Search menu → Workflow Templates
  1. Open Workflow Automation → Workflow Mapping and expand the first mapping to review its triggering attributes and conditions.
    Search menu → Workflow Mapping
  1. Explore the available attributes and logical constructs. Because the SDC access is read-only for this activity, do not save changes; select Reset when finished.
✓
Expected result

You can explain how a Workflow Template defines actions and how Workflow Mapping conditions determine when that workflow runs.

✓
Lab 12 complete

You have completed the activities defined for Manage Incidents with Zscaler Workflow Automation.
