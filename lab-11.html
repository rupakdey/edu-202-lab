Manage Incidents with Workflow Automation

Inspect DLP incidents and understand the source lab’s metadata, notification, escalation and automated-workflow actions.

5 tasks Approx. 20 minutes SDC · permission-dependent actions
Lab objectives

What you will accomplish

  • Enroll the workstation using the supplied SDC IT identity.
  • Inspect incident metadata, violation details and state history.
  • Review update/notification/escalation actions subject to SDC permissions.
  • Explore workflow templates and mapping conditions without saving changes.
!
SDC permissions determine the exercise mode

The source describes SDC as read-only but also includes incident-update and notification tasks. Use an instructor-approved training incident. If the assigned account cannot save or send, inspect the controls and follow the instructor demonstration; do not treat disabled actions as a fault.

11.1

Enroll ZCC with the SDC IT Identity

Switch the endpoint from the dedicated learner tenant to SDC.

  1. On Corp Client PC 1, open ZCC and Log Out of the learner tenant.
  2. In CloudShare → Credentials, find the SDC IT department identity. Sign in to ZCC with that username and its corresponding SDC password; complete the IdP prompt.
  3. Wait several minutes if needed. Verify the Internet Security service reports ON and the network type is Off-Trusted Network in this lab.
✓
Expected result

ZCC is enrolled with the assigned SDC IT identity and Internet Security is ON.

11.2

Inspect a DLP Incident

Examine the event and the data that triggered it.

Search Menu → Incidents
Zscaler Help: Incidents ↗
  1. Sign in to the Experience Center with the SDC administrator account. Open Incidents and select the instructor-designated training incident by Transaction ID.
  2. Review Overview and Violation Details. Note the user, policy/rule, time, status and available incident metadata.
  3. In Violation Content, expand View Trigger Data and inspect the matched content.
✓
Expected result

You can identify the training incident, its metadata, and the content associated with the DLP trigger.

11.3

Review or Update Incident Metadata

Understand status, priority and the audit history.

!
SDC permissions determine the exercise mode

The source describes SDC as read-only but also includes incident-update and notification tasks. Use an instructor-approved training incident. If the assigned account cannot save or send, inspect the controls and follow the instructor demonstration; do not treat disabled actions as a fault.

  1. Open the incident’s Actions menu. Review the status controls. If your instructor enables updates, set Status → Investigating and enter Test in the note field.
  2. Select Assign Priority. If permitted, set High unless it is already selected.
  3. Refresh and inspect State Changes. Verify the demonstrated or permitted status/priority changes are recorded.
✓
Expected result

You can explain how status and priority updates appear in State Changes; if authorized and permitted, the saved values are Investigating and High.

11.4

Review Notification and Escalation Workflows

Follow the training incident through user notification and approval.

!
SDC permissions determine the exercise mode

The source describes SDC as read-only but also includes incident-update and notification tasks. Use an instructor-approved training incident. If the assigned account cannot save or send, inspect the controls and follow the instructor demonstration; do not treat disabled actions as a fault.

  1. Open Actions → Notify User. Select the demonstrated language/time zone and enter the source note below. Submit only when the instructor has approved sending to the training user.
    Please justify uploading this document for testing purposes of HandsOnLab
  2. Review State Changes for a notification event. A user response may not arrive during the session; continue with the instructor demonstration.
  3. Use Search Menu → Approvers. If the instructor permits creating a training approver, select Add more (+), enter your approved name/email, and Save. Otherwise inspect an existing training approver.
  4. Return to the same incident. Open Actions → Escalate, choose the approved training approver, and Save only when permitted.
  5. If an escalation email is delivered to your approved address, open its incident link. Select Approved for Justification Type, enter a reason, and Submit. Review the incident’s State Changes for the outcome. In read-only mode, inspect the source example with the instructor.
✓
Expected result

You can trace notification and escalation through the incident history. Sending and approval are confirmed only if the permitted training workflow actually completes.

11.5

Inspect Automated Workflows

Review templates and their matching conditions without saving changes.

Search Menu → Workflow Templates
Zscaler Help: Workflow Templates ↗
  1. Open Workflow Templates. For Auto Escalate, select View Workflow Template.
  2. Follow the displayed sequence and branches to understand which action occurs and when the workflow waits for a response.
  3. Open Workflow Mappings. Expand the first mapping and inspect its triggering attributes and conditions.
  4. Explore the available logic without saving changes. Select Reset when finished. A workflow runs only when an incident matches its mapping.
✓
Expected result

You can identify the actions in an existing workflow and the conditions that trigger it; no mapping changes are saved.
